# IMPORTANT PRODUCT DECISIONS

## 1. Categories are INDEPENDENT

Categories must NOT belong to Projects.

The relationship is:

Expense
├── Project (optional)
├── Category (required)
├── Labels (multiple, optional)
├── Amount
├── Date
├── Payment Method
└── Notes

Example:

Expense: ₹2,500 Hotel

Project: Qatar Move
Category: Travel
Labels: Personal, Important

Another expense:

Expense: ₹850 Dinner

Project: None
Category: Food
Labels: Personal

Categories must be reusable across all projects.

# IMPORTANT DEVELOPMENT RULES

## Rule 1 — Do not skip stages

Complete only the current stage.

Wait for my approval before proceeding.

## Rule 2 — Do not rewrite working functionality unnecessarily

When implementing later stages, preserve existing functionality.

## Rule 3 — Use reusable components

Create reusable:

- Buttons
- Inputs
- Modals
- Selects
- Date pickers
- Tables
- Cards
- Charts
- Empty states
- Loading states
- Confirmation dialogs

## Rule 4 — Keep business logic separate

Do not put complex database/business logic directly inside UI components.

Use appropriate:

- Services
- Hooks
- API functions
- Repository/data-access layer

## Rule 5 — Validate everything

Validate both frontend and backend/server-side.

Never rely only on frontend validation.

## Rule 6 — No unnecessary features

Do NOT add:

- Bank integrations
- Investment tracking
- Accounting
- Tax management
- Invoicing
- Payroll
- Cryptocurrency
- Complex budgeting

unless explicitly requested later.

This is a **personal expense manager**, not enterprise accounting software.

## Rule 7 — Currency

Make currency configurable.

Default:

INR (₹)

Allow changing the default currency later through Settings.

## Rule 8 — Dates

Store dates consistently in the database and handle timezone correctly.

Display dates according to the user's configured timezone.

## Rule 9 — Amounts

Never use floating-point arithmetic for financial calculations where avoidable.

Use appropriate decimal/numeric database types.

## Rule 10 — Confirm destructive actions

Deleting expenses, projects, categories, or labels should require confirmation.

Prefer archive/deactivate behaviour where appropriate.
